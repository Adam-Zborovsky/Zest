# M4 review — accepted 2026-09-12

Adam approved the M4 plan including the coverage recommendation: matching runs client-side against the chosen discovery results because the provider reserves multi-ingredient filtering for premium keys. The main agent implemented the milestone; a fresh independent reviewer inspected the full commit range, re-ran analysis and the complete suite, and challenged the classification tables, matching logic, run engine, UI accessibility, and boundary compliance.

## Findings closed

1. **Re-running matching duplicated every result.** `start()` seeded the new run with the previous run's matches, so pressing "Find matches" after a done, paused, or in-flight run appended the whole scope a second time (empirically reproduced by the reviewer: 4 recipes → 8 matches). Fresh starts now use empty accumulators — only `resume()` retains a paused run's partial matches — and the button is disabled with a visible explanation while a run is checking. Regressions cover both re-press paths (provider level and UI level).
2. **Uncommitted decision record.** The M4 contract docs were written but not yet committed when the review ran, and the classification tables referenced this file before it existed. The contract ([BAR.md](../BAR.md)), the garnish/substitution tables and endpoint record in [DATA.md](../DATA.md), the design application note, and this review now land together with the code.
3. **Documentation precision.** `optionalGarnishes` now documents that selected garnishes are covered and never reported; the done-state summary reads "Finished checking" so it no longer appears to contradict the "could not be opened" line; the design note no longer claims the coverage footnote is announced (it is always visible, the summary is announced).
4. **Test and code hygiene.** The keyboard test now completes an entire selection and match run without a pointer (tab → Enter opens the sheet, Space toggles an option, Enter confirms, Enter starts matching), with Escape-close retained elsewhere; the `list.php` request URL shape is asserted like the other four endpoints; the dead `reset()` notifier method was removed; the Riverpod notifier-instance-reuse assumption behind run abandonment is now documented at the token with its verification note.
5. **Garnish word-order gaps recorded.** Provider forms like "sprig of mint" or "brandied cherries" stay essential because only the reviewed suffix and whole-name forms are excluded; DATA.md now states explicitly that unclassified names always fail toward "missing" and that additions are evidence decisions.

## Verdict

The independent review returned BLOCK on the duplication defect and the uncommitted record; both were fixed and the complete **124-test** suite, clean analysis, and a release web build were re-verified afterward. The reviewer confirmed: classification tables match the documented rationale with no invented equivalences; the three categories are computed soundly with deduplication by normalized identity and the "unselected is not available" rule enforced; batching, pause/resume, and unavailable-lookup accounting behave per contract; no source recipe is modified, nothing persists, no provider content entered the repository, and no M5/M6 features or new dependencies were introduced. Acceptance criteria — matching unit tests including the three named edge cases, and a results UI distinguishing the three cases — are met.

Automated checks are not a screen-reader certification; physical TalkBack/VoiceOver sessions and live provider traffic remain untested, and golden comparisons are scoped to this machine's Flutter renderer. M5 has not started and requires its own milestone plan.
