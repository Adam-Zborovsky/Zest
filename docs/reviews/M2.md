# M2 review — accepted 2026-09-11

Scope: TheCocktailDB V1 data layer only. Adam approved the M2 plan and explicitly requested a Terra subagent. The main agent retained domain/architecture decisions; `gpt-5.6-terra` implemented the HTTP client, cache, error surface and client tests. A separate agent reviewed the domain and another independently reviewed the integrated result. Reviewers did not author the code they accepted.

## Findings closed

1. **Measure punctuation was too permissive.** Removing every period allowed `1 o..z` to parse as ounces. A regression first failed with expected null / actual 1.0; parsing now allows only letters and an optional trailing period. Both malformed dotted forms are rejected without losing source text.
2. **Round-trip wording overstated preservation.** Blank ingredient slots discard orphan measures. The documented contract now explicitly preserves supported metadata and named ingredient pairs, not unknown fields or unnamed slots; a dedicated test covers the boundary. This matches the provider's numbered-pair guidance without inventing ingredients.
3. **Abort alone did not guarantee completion.** A non-cooperative injected client could ignore a timeout signal. The complete send/body operation now races timeout/close, sends an abort signal, and rejects late success. Regression tests cover cooperative transports, non-cooperative pending requests, late completion and stalled body streams.
4. **Key path and error safety needed explicit guards.** API keys must be nonempty safe path segments and invalid-key errors do not echo the value. Transport exceptions containing a synthetic secret/URI are mapped to sanitized typed failures. Redirects are disabled.
5. **Transport assertions were incomplete.** Added direct tests for response-body caps, stream failures, post-header timeout, 429 status and Retry-After seconds, redirect flags, immutable result lists, zero TTL and invalid runtime settings. Replaced the earlier weak failure test with an actual URI-bearing client exception.

## Review conclusions

- Full recipes and ingredient-filter summaries cannot be confused. Named measures, instructions and supported attribution fields retain their source values; ingredient slots remain aligned across gaps.
- The alias table only normalizes lexical/plural identity; it does not merge brands, rum varieties or preparation forms. Every mapping and intentionally distinct example is tested.
- Successful typed parsing precedes cache insertion. Entries are bounded by count with TTL/LRU, empty matches are cached, concurrent identical operations share a request, and errors are not cached. No automatic retries or ingestion were added.
- Only the agreed `http` dependency and Android Internet permission were introduced. Android/web wrappers remain; `backend/` remains untouched. There is no discovery UI, backend, persistence, source-image download, provider fixture or private key.
- The data contract documents the limited measure grammar, semantic serialization boundary, integer-seconds-only Retry-After parsing, client-side key visibility and unresolved publication rights. None is silently presented as a solved later-milestone decision.
