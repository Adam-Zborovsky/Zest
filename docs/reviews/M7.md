## Findings and resolutions

| # | Severity | Finding | Resolution |
| --- | --- | --- | --- |
| 1 | Major | `PrefsAuthRepository.continueOnDevice` wrote `currentProfile` before `lastProfile` as separate writes. If the second failed, the person saw an error but a relaunch came back signed in. | Fixed in commit `bdd413d`. Write order reversed: `lastProfile` first, `currentProfile` last. Relaunch regression tests confirm both write paths. |
| 2 | Minor | `main()` has no handling if `SharedPreferencesWithCache.create` throws; the app never renders. | Accepted as documented limitation. The app cannot run without its flag store; revisit alongside deferred Android lost-photo recovery. |
| 3 | Note | `LoginScreen._continue` catches only `SessionStorageException`; `ArgumentError` for an overlong name is unreachable today because the field's `maxLength` is at least as strict, but the coupling is implicit. | Fixed in commit `e20562f`. Login now catches `ArgumentError` and states the name limit inline. |
| 4 | Note | Progress counts login as step 5 of 5 while the `PageView` shows 4 pages. | Verified as intentional per `ONBOARDING.md`: login counts as step 5. |
