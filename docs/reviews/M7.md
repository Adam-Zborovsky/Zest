## Findings and resolutions

| # | Severity | Finding | Resolution |
| --- | --- | --- | --- |
| 1 | Major | `PrefsAuthRepository.continueOnDevice` wrote `currentProfile` before `lastProfile` as separate writes. If the second write failed, the person saw an error, but a relaunch came back signed in. | Fixed in `bdd413d`. `lastProfile` is written first and `currentProfile` last. Relaunch tests fail each write in turn; the `lastProfile` case fails against the old order. |
| 2 | Minor | `main()` has no handling if `SharedPreferencesWithCache.create` throws, so the app never renders. | Accepted as a documented limitation. The app cannot run without its flag store; revisit alongside the deferred Android lost-photo recovery. |
| 3 | Note | `LoginScreen._continue` caught only `SessionStorageException`. An `ArgumentError` for an overlong name is unreachable today, because the field's `maxLength` is at least as strict, but the coupling was implicit. | Fixed in `e20562f`. Login also catches `ArgumentError` and states the name limit inline. |
| 4 | Note | Progress counts login as step 5 of 5, while the `PageView` shows 4 pages. | Intended, per `docs/ONBOARDING.md`. |
