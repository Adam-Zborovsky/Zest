## Checked and found correct

- **Wire contract:** sort order, deduplication and the version hash; `If-None-Match` lists, weak tags and `*`; the 503 before first publish; `no-cache` scoped to the catalog route only.
- **Refresher:** all-or-nothing transactional publish; a failure never overwrites the previous catalog; an empty total counts as a failure; one self-rescheduling timer with capped backoff and `retryAfter`; prompt retry after a restart that follows a failure; `close()` behavior; no logging.
- **Endpoint reads:** state and recipes are read as a consistent pair, and the in-memory body cache is keyed by version.
- **Client storage:** the schema 2 upgrade drops and recreates the catalog tables. `applySnapshot` diffs and writes in one transaction. The snapshot client validates like the gateway, with an 8 MB limit and typed errors.
- **Update behavior:** first launch is silent; launch apply shows a notice; nothing is shown on 304 or a no-op; manual apply works; concurrent triggers coalesce; the run token blocks stale writes; the search index is invalidated after each apply.
- **Search:** folding, tier order and tie-breaks, and alias handling. The "creme", "lime jiuce" and "old fash" cases pass in unit tests and in the real Discover screen. Constellation suggestions are limited to graph nodes, and the home-bar list uses the shared ranking.
- **Discover and detail:** deep links and query parameters are preserved; detail and bar matching read the local catalog first and fall back to `lookup.php`.
- **Accessibility:** 48 px option targets, the kind of item in each semantic label, reduced motion, and a polite, non-auto-hiding notice with a 48 px Dismiss. The reviewer inspected all 7 changed goldens.
- **Terms and fixtures:** all fixtures are synthetic and no provider images are stored. The accepted-risk note in `SOURCES.md` matches the behavior. No references to the removed letter-sync APIs remain.

## Resolution

All 20 findings are fixed. The fix pass landed on `Development` in merge `714883a`. It was a single Sonnet pass, interrupted twice by session limits and resumed from its worktree.

| # | How |
| --- | --- |
| 1 | `If-None-Match` added to the CORS allowed headers. Covered by a preflight test. |
| 2 | The resume check applies immediately while the catalog is empty. The 6-hour gate is measured from the last attempted check, successful or not. |
| 3 | The launch check runs from the app shell after the first frame. The controller invalidates every provider derived from the catalog after an apply, so screens no longer rely on listeners armed by Home. Covered by a cold-launch test to `/discover`. |
| 4 | `ZestSuggestionField` accepts `labelText`, and the variation editor passes `'Ingredient'`. The golden was regenerated and inspected: filled rows show the label, matching Measure. |
| 5 | A staged snapshot is cleared by any immediate apply and discarded if the applied version moved since staging. `applyStaged` is coalesced. |
| 6 | Repository failures land in `failed(unknown)` with Retry. Covered by a throwing-repository test. |
| 7 | The staged notice reads "Catalog update available", with an Update action. The notice listener lives at app level. Widget tests cover the staged notice, the applied notice, the Update action, and staging while on a non-Home route. |
| 8 | Highlight changes are announced with `SemanticsService.sendAnnouncement`. |
| 9 | The count live region is a zero-size semantics node. It is cleared on Escape and on selection, and is not triggered by programmatic rewrites. |
| 10 | Typo matches are only a fallback when tiers 1–4 are empty. The equal-length-prefix typo rule needs a query word of 5+ characters. |
| 11 | An unknown ingredient identity falls back to an exact accent-folded match. |
| 12 | The results screen has the empty-catalog gate, with a test. |
| 13 | The demo uses `lookup.php` and exits 0 without network access. Dead `filter.php`/`list.php` code is removed from the gateway, the fixture and the Flutter fake. |
| 14 | `DATA.md` marks the old client API as historical. `CONSTELLATION.md` invalidation wording and the typo are fixed. `VERIFICATION.md` records every track and every golden. `ROADMAP.md` status is updated. |
| 15 | Home and home-bar copy reads "downloaded catalog", without the doubled article. Goldens regenerated and inspected. |
| 16–18 | `Vary: Origin, Accept-Encoding` is appended rather than overwritten. `gzip;q=0` is respected. A 304 is answered from the catalog state alone, without reading recipe rows. |
| 19 | `CatalogStatusCard` moved to `lib/features/catalog/presentation/`. |
| 20 | An id→Recipe map is kept beside the index. `lookupRecipeLocalFirst` uses `ref.read`. |

The fix pass also caught two latent bugs outside the findings list:

- `showZestNotice`: it looked up the Overlay from the Navigator's own ancestor context.
